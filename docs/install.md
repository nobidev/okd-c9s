# Installing a cluster from the rebuilt release

The examples use the default image names (`make info` prints yours).

```bash
RELEASE=ghcr.io/nobidev/okd-c9s/release:4.22.0-okd-scos.10-c9s   # or a 4.20 / 4.21 one
```

## 1. Make the images pullable

GHCR packages start out private. Either make the `okd-c9s/*` packages public,
or merge a `ghcr.io` credential into the pull secret used in
`install-config.yaml`.

## 2. Get `openshift-install` and `oc` for this release

```bash
oc adm release extract --command=openshift-install --to=. "$RELEASE"
oc adm release extract --command=oc --to=. "$RELEASE"
./openshift-install version   # must print the c9s release image
```

`oc adm release extract` pins the extracted installer to `$RELEASE`, so no
`OPENSHIFT_INSTALL_RELEASE_IMAGE_OVERRIDE` is needed.

## 3. Boot images

Nodes must boot from **SCOS 9** media; SCOS 10 media cannot even start
Ignition on an x86-64-v2 CPU. The artifacts (live ISO, PXE kernel /
initramfs / rootfs, metal raw image, qcow2) are listed in
`build/bootimages/stream.json` (generated by `make bootimages`).
After Ignition, every node rebases to the `stream-coreos` image of the
release, i.e. the c9s node image built here.

### Platform `none` / bare metal UPI / SNO

```bash
./openshift-install create ignition-configs        # or: create single-node-ignition-config
# boot each machine from the SCOS 9 live ISO / PXE and run:
sudo coreos-installer install /dev/sda --ignition-url http://<server>/master.ign
```

### Agent-based installer

`openshift-install agent create image` takes its base ISO from the release's
`machine-os-images` component, which carries the SCOS 9 ISO here. Check the
log line `Using base ISO image ...` and confirm the resulting ISO boots on the
target CPU before rolling out.

### Installer-provisioned infrastructure (vSphere, OpenStack, KubeVirt, …)

The `openshift-install` binary still embeds the SCOS 10 stream metadata, so
point it at a SCOS 9 image explicitly, e.g. for vSphere:

```yaml
platform:
  vsphere:
    clusterOSImage: https://<mirror>/scos-9.0.<build>-vmware.x86_64.ova?sha256=<sha256>
```

The CoreOS pipeline publishes only metal and qemu artifacts for SCOS 9, so
platform-specific images (OVA, OpenStack qcow2) have to be produced with
coreos-assembler (`cosa buildextend-*`) from `upstream/rhel-coreos-config`.

## 4. Hypervisors

Use a CPU model that matches what the hosts provide (e.g. Proxmox
`x86-64-v2-AES`, libvirt `Nehalem`/`Westmere`). `make verify` emulates
`Nehalem` by default (`QEMU_CPU=Westmere` etc. to change).
